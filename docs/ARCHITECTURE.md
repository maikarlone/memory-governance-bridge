# Architecture

状态：参考设计，未实现为生产系统。  
适用范围：本地单用户/小团队的只读记忆接入侧车；不包含记忆内核实现。

## 1. 定位

本项目的目标不是“再做一个记忆数据库”，而是给已有记忆内核加一层**可审计、可回滚、默认关闭的只读接入层**：

```text
Agent / IDE / Workflow
        │  MCP stdio
        ▼
  MCP bridge（只读工具）
        │  HTTP
        ▼
  Read-only adapter（身份绑定 + 空结果语义 + 观察模式）
        │  HTTP
        ▼
  Memory core（L0/L1，外部依赖）
```

边界：

- 不实现向量库、抽取模型或 L0/L1 存储。
- 不改内核；适配层只做身份绑定和结果标记。
- 三端默认只读；写入路径只在设计层存在。

## 2. 设计原则

### 2.1 只读优先

- 三端只暴露 `recall`，不暴露 `write/remember/capture`。
- 适配层没有写路由；写入只能走受控脚本和人工审批。
- 读请求不接受客户端传入的 team/agent/user 身份；身份由 token 绑定。

### 2.2 默认关闭

- 桥默认 `MEMORY_BRIDGE_ENABLED=0`；未显式开启时直接返回 `disabled`，不发起任何网络请求。
- 适配层默认 observe 模式：只标记 `low_relevance`、`no_direct_answer`，不静默过滤。
- 生产写入开关默认关闭。

### 2.3 token 不落配置

- token 只从环境变量或操作系统密钥环读取。
- 仓库中不出现 token 文件、`.env`、密钥、真实凭据。
- 日志和错误信息不打印 token；示例配置只写占位符。

### 2.4 逐端回滚

- 每个客户端独立 token、独立绑定、独立开关。
- 单端出问题时可单独停用，不影响其他端。
- 回滚顺序：停桥 → 恢复该端配置 → 重启该端 → 验证该端只读。

### 2.5 空结果语义化

适配层和桥必须区分：

| 状态 | 含义 | 使用方式 |
|---|---|---|
| `ok` | 有结果 | 引用时带 record_id/来源 |
| `no_match` | 没有匹配 | 明确说“记忆里没有” |
| `service_down` | 服务不可达 | 提示启动服务，按无记忆回答 |
| `low_relevance` | 结果低于相关阈值 | 不当作答案 |
| `no_direct_answer` | 结果没有直接回答问题 | 第一句说“记忆里没有这条” |

空结果不能被相近内容替代；`ok` 也不等于“可直接回答”。

### 2.6 人工审批

- 写入路径：草稿 → 预检 → 人工批准 → 入库 → 抽取一致性检查。
- 批量抽取默认每批一条，避免多条事实被截断或合并。
- 审批必须绑定批次、快照和回滚点。

### 2.7 写入路径设计

写入路径只存在于设计和受控脚本中：

- 幂等：`project_id + content_hash + source_identity`。
- 相同内容不同来源不新增 L1，只追加上来源审计。
- 冲突以当前文件为准；旧记录标记 `superseded`，不物理覆盖。
- 审计日志记录批次、前后计数、来源和回滚范围。

## 3. 三端接入差异（泛化）

三端共用同一套桥和适配层，差异只在“规则放哪里、何时加载”：

| 端 | 接入方式 | 规则加载 | token 生效 |
|---|---|---|---|
| 桌面 Agent | 本地技能 + MCP stdio | 技能可热加载 | 通常需重启桥/会话 |
| IDE Agent | 工作区规则 + MCP stdio | 新会话加载 | 新会话生效 |
| 工作流 Agent | 用户级技能 + MCP stdio | 重启 Gateway 后加载 | 新会话/重启后生效 |

共同点：

- 都是 stdio MCP；都由 wrapper 读取环境变量和 token。
- 都只读；都不允许把 token 写进规则或配置。
- 都必须在回答前判断“结果是否直接回答问题”。

## 4. 已知限制

### 4.1 近分排序

向量检索可能出现近分并列：状态句和定义句分数只差很小，top-1 可能不是最直接答案。当前只标记 `answer_match`，未参与排序；需要在适配层做近分重排或改写事实。

### 4.2 抽取截断

批量抽取时，模型输出可能被截断或合并，导致 N 条事实只生成少于 N 条 L1。默认改为每批一条，并在入库后做条数与语义一致性检查；不一致回滚。

### 4.3 规则遵从

规则文件能降低误答，但不能保证模型 100% 遵从；负例仍可能被本地文件推理绕过。对外使用前必须用负例回归，不能只依赖提示词。

### 4.4 非生产属性

- 没有多租户鉴权、配额、审计合规和 SLA。
- 没有生产级密钥管理；示例只使用环境变量。
- 没有自动故障转移；服务停止时只返回 `service_down`。

## 5. 非目标

- 不做通用记忆数据库。
- 不做自动写入、自动学习、自动改事实。
- 不做生产多租户。
- 不把真实项目数据、日志、快照或凭据放进仓库。

## 6. 结论

**参考实现，非生产就绪。**
